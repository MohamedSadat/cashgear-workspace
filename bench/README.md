# Benchmarks and harnesses

Phase 0's spikes (S1 to S9) left these harnesses. Their results are in `docs/DECISIONS.md`
(2026-11-11: Phase 0 results). `results/` is what a run writes; it is not committed, and CI
uploads it as an artifact.

| Path                                                                                  | Spike              | What                                                                                                                                                                                                                                                    | Runs                                                                                                                   |
| ------------------------------------------------------------------------------------- | ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| `editor/` (`@cgw/bench-editor`)                                                       | S1, S2, S5, S6, S7 | Phase 0's editor model: the block container schema, the block-id plugin, the Yjs seam, block commands, a simulated network, a document generator. Phase 1 replaces the model with `packages/doc` and `packages/editor` and points the harnesses at them | —                                                                                                                      |
| `editor/src/s1-fuzz.test.ts`                                                          | S1                 | Two and three editors, random operations, random delivery, offline spells; checks convergence, schema validity, unique ids, ids kept on move, and explains every lost token                                                                             | `pnpm test` (1,500 operations); `S1_OPS=10000 S1_SEEDS=3 S1_COMPARE=1` for the full run                                |
| `editor/src/s1-scenarios.test.ts`                                                     | S1                 | Each S1 criterion as an exact case for every binding                                                                                                                                                                                                    | `pnpm test`                                                                                                            |
| `editor/src/s2-version-gate.test.ts`                                                  | S2                 | An older build meets a newer document, with and without the gate                                                                                                                                                                                        | `pnpm test`                                                                                                            |
| `editor/src/yjs-pending.test.ts`                                                      | S1                 | The Yjs 13.6.33 pending-update case S1 found, and the retry that heals it                                                                                                                                                                               | `pnpm test`                                                                                                            |
| `editor/src/s3-corpus.test.ts`, `s3-verify.test.ts`, `ydoc-check.mjs`, `ydoc-dotnet/` | S3                 | Yjs 13 writes a corpus; `cgw-ydoc` processes it from .NET 10 by P/Invoke; Yjs 13 checks every output; malformed input; compaction timed                                                                                                                 | `pnpm bench:s3` (`S3_DOCS`, `S3_BIG_BYTES`)                                                                            |
| `editor/run-browser.mjs`, `webview2-host/`                                            | S5, S6, S7         | The RTL and Arabic input checklist, the editor budgets, and hostile content, in Chrome and in WebView2 (a `wry` window driven over CDP)                                                                                                                 | `pnpm bench:webview2-host` once, then `pnpm bench:browser [-- --s5 --s6 --s7 --chrome --webview2]`                     |
| `sequence-dotnet/`                                                                    | S8                 | 50 writers and 8 readers on one page in SQL Server, under the page-row lock and against an `IDENTITY` control. Creates and drops the scratch database `cgw_spike_s8`                                                                                    | `pnpm bench:sequence` (needs LocalDB; not in CI)                                                                       |
| `sheet-embed/`                                                                        | S9                 | Sheet's deployed web app in a sandboxed iframe, from a parent without COEP and from an isolated one, in Chrome and WebView2                                                                                                                             | `pnpm bench:sheet-embed` (needs the network and a local `cashgear-sheet` checkout for its fixture workbook; not in CI) |

CI runs S1, S2, S3, S5 and S7 (Chrome) on every push, and S6 (Chrome) as the first rows of the
benchmark history; budgets are gated from Phase 1. WebView2 runs of S5 to S7 are local: on a
hosted runner the WebView2 host is elevated and ignores the debugging switch.
